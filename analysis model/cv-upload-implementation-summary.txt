2. KEY DECISIONS & ARCHITECTURE
==============================================================================

STATE MANAGEMENT:
─────────────────
• Chose React Context API over Redux/Zustand for simplicity
• CVContext provides:
  - Centralized CV data storage
  - Polling logic for background analysis
  - Error handling and recovery
  - Ready for future expansion (e.g., CV history, multiple uploads)
• Token stored in localStorage for authentication
• CVData accessible globally via useCV() hook from any component

POLLING STRATEGY:
─────────────────
• Backend processes CV asynchronously in background task
• Frontend polls GET /api/v1/cv/latest every 1 second
• Max 60 polling attempts = ~60 second timeout
• Provides good UX: responsive while showing "Analyzing..." state
• Can be optimized with WebSockets later if needed

FILE VALIDATION:
────────────────
• Client-side: File size, file type, required fields
• Server-side: Duplicate validation in cv_service.py
• Supports: PDF, DOCX, DOC, TXT (most common CV formats)
• Max file size: 50MB (configurable via settings.MAX_UPLOAD_SIZE_MB)

TEXT EXTRACTION:
────────────────
• PDF: pdfminer.six.extract_text() - handles scanned PDFs, images
• DOCX: python-docx for proper XML parsing
• TXT: Direct UTF-8 read with error handling
• Fallback: Returns error message if extraction fails (graceful degradation)

AI ANALYSIS:
────────────
• Model: OpenAI gpt-4o-mini (cost-effective, fast)
• Features extracted:
  - Score (0-100): CV quality and competitiveness
  - Skills (array): Up to 12 extracted technical/professional skills
  - Strengths (array): 3 top strengths identified
  - Recommendations (array): 4 actionable improvement suggestions
  - Best Fit Role (string): AI-recommended position (e.g., "Senior Frontend Engineer")
• Response format: JSON (structured, machine-readable)
• Temperature: 0.3 (deterministic, consistent results)

DISPLAY COMPONENTS:
───────────────────
• Score Card: Circular gauge showing 0-100, color-coded feedback
• Role Card: Displays best-fit role with briefcase emoji
• Skills Section: Skills rendered as chips/tags for visual clarity
• Strengths Section: List with bullet points and icons
• Recommendations Section: Actionable suggestions for CV improvement
• Proceed Button: Green button to advance to interview stage
• Error States: Clear messaging with retry functionality

3. API ENDPOINTS USED
==============================================================================

Upload CV:
──────────
POST /api/v1/cv/upload
Headers: Authorization: Bearer <token>
Body: multipart/form-data (file)
Response: CVUploadOut { id, filename, score, status, ... }
Status codes: 201 (success), 413 (file too large), 415 (invalid type)

Fetch Latest Analysis:
──────────────────────
GET /api/v1/cv/latest
Headers: Authorization: Bearer <token>
Response: CVUploadOut { score, skills, best_fit_role, status, analyzed_at, ... }
Status: 200 (found), 404 (not uploaded yet)

Get All CV History:
────────────────────
GET /api/v1/cv/history
Headers: Authorization: Bearer <token>
Response: List[CVUploadOut]

Delete CV:
──────────
DELETE /api/v1/cv/{cv_id}
Headers: Authorization: Bearer <token>
Response: MessageResponse { message: "CV deleted" }

7. KNOWN LIMITATIONS & FUTURE IMPROVEMENTS
==============================================================================

CURRENT LIMITATIONS:
─────────────────────
1. No OCR for image-based PDFs (pdfminer works with text PDFs only)
   → Users with scanned CVs will see empty/partial text
   → Solution: Integrate Tesseract OCR or cloud-based service

2. Polling instead of real-time (max 60-second latency)
   → Solution: WebSocket implementation

3. No user confirmation for "Proceed to Interview"
   → Should ask: "Ready to proceed? Your CV score: 85/100"

4. CV data not persisted to "next stage" properly
   → Interview.jsx needs to read from CVContext

5. No rate limiting on CV uploads
   → Users could spam uploads, abuse OpenAI quota

6. Basic error messages (could be more user-friendly)
   → "Failed to upload CV" doesn't explain why

10. PERFORMANCE METRICS & OPTIMIZATION
==============================================================================

Current Performance:
─────────────────────
• File upload: ~1-2 seconds (depends on file size & connection)
• PDF text extraction: ~2-5 seconds (depends on PDF complexity)
• OpenAI analysis: ~5-15 seconds (depends on model & CV length)
• Total E2E: ~10-25 seconds

Optimization Opportunities:
────────────────────────────
1. Compress PDF/DOCX before upload (server-side compression)
2. Cache OpenAI responses for duplicate CVs (hash-based)
3. Batch process multiple CVs if users upload many
4. Lazy load results (show score first, then skills incrementally)
5. Use smaller model (gpt-3.5-turbo) for faster analysis
